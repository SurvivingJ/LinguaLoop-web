対象語：{word}
品詞：{pos}

学習者レベル：{complexity_tier}
語義：{definition}
主要連語相手：{primary_collocate}

基礎例文：
{sentences_json}

次に挙げる練習レベルのみを生成する：{active_levels_json}

共通ルール：
1. すべての出力値は日本語で記述し、英語を混ぜないこと。
2. 有効な JSON のみを出力し、キーは数字文字列を使う。
3. 各選択肢の形式："1" = 選択肢テキスト，"2" = 真/偽（正解かどうか、JSON の真偽値 true/false），"3" = 短い教育的解説（日本語）。
4. 解説は短く・明確で、教育的価値のあるものにする。
5. 対象語は一つの完全な語として扱う。L3・L5・L6 において、ディストラクターや代替文中の対象語は、固定した義項と同じ統語／意味役割を担うこと（対象語の文字を別語の断片として使ってはいけない。P1 ルール 13 参照）。

L1（聞き取り — リスニング練習）：
- 場面：学習者は対象語の「音声」（合成音声が一度だけ読み上げる）を聞き、4 つの書記選択肢から正しい表記を選ぶ。
- 選択肢の数：1 つが正解 = 対象語、ディストラクターは 3 つ以上 5 つ以下（つまり選択肢は 4〜6 個）。
  - 学習者に見えるのは 4 つだけで、ディストラクターは後段の審査を通ったものから 3 つが選ばれる。多めに出すのは、審査で落ちたときの余裕を作るためである。
  - ただし数は目標であって義務ではない。実在する語が 3 つしか見つからなければ、ディストラクターは 3 つでよい。**数を満たすために語を作ることは、最も重い違反である。**造語を 5 つ並べた解答は、実在する語を 3 つ並べた解答より確実に悪い。
- ディストラクターの探し方（この手順で探すこと）：
  1. 対象語の読みをモーラに分ける（例：「むかし」→ む／か／し）。
  2. 一つのモーラだけを別のモーラに置き換えた読みを、位置ごとに順に作る（し→い、し→え、し→で、か→こ …）。
  3. その読みが実在する語かどうかを一つずつ確かめる。実在するものだけを採用する（「むかし」なら「むかい（向かい）」「むかえ（迎え）」「むかで（百足）」などが見つかる）。
  4. 実在しない読みは捨てる。捨てた結果 3 つしか残らなければ、それが答えである。
- 関門 1（実在性）— ここが破れると問題全体が捨てられる。最優先で守ること：
  - ディストラクターは国語辞典に見出し語として載っている語だけを使う。
  - 解説を書く前に、その語の「読み」と「意味」を自分の言葉で言えるか確かめる。言えないものは実在しない語なので捨て、別の語に差し替える。
  - 音を合わせるために漢字を組み合わせて語をこしらえてはならない（「向こうし」「無蚊地」「無蚊」「むかけ」「むかっ」のような造語はすべて禁止。これらは実際に生成され、すべて審査で落とされた）。地名・人名だと称して未確認の語を通してもならない。
- 関門 2（表記）：
  - 正解の選択肢は、対象語を日本語で普通に書くときの表記そのままにする。
  - ディストラクターも、その語を普通に書くときの表記で書く。
  - 対象語の字種（漢字／かな）に揃えるために表記を作り替えてはならない。かなで書くのが普通の語を無理に漢字に直さないこと。
- 関門 3（音）：ディストラクターは対象語とモーラ単位で「一箇所だけ」異なること。次のいずれかに当てはまればよい：
  - 一モーラだけが違う最小対（母音でも子音でもよい。例：「むかし」↔「むかえ」、「きかい」↔「きかん」）。
  - 清濁・半濁の対立（例：「かき」↔「かぎ」、「さる」↔「ざる」）。
  - 長短母音の対立（例：「ビル」↔「ビール」、「おばさん」↔「おばあさん」）。
  - 促音の有無（例：「ぶか」↔「ぶっか」）。
  モーラ数が二つ以上離れている語、二箇所以上が異なる語は使わない（対象語「むかし」に対する「むし」「むこう」は不可）。
- 関門 4（使ってはならないもの）：
  - 対象語の同義語・類義語（音を聞いた学習者が正解として選びうるため）。
  - 対象語と読みもアクセントも同じ同音異義語。合成音声は一通りにしか読まないので、学習者には決めようがない（「機械」に対する「機会」、「箸」に対する「橋」は不可）。
  - 高低アクセントだけが異なる語も、同じ理由で不可。
  - 表記だけが似て読みが異なる語（聴覚で区別できてしまう形近語。これはリスニング練習を壊す）。
  - 対象語そのもの、および対象語の活用形（「作る」に対する「作った」は不可）。
- 出力前の最終点検：出そうとしているすべてのディストラクターについて、順に「読み」「意味」「対象語とどのモーラが違うか」を心の中で述べる。一つでも述べられないものがあれば、実在する別の語に差し替えてから出力する。
- 解説："2"=false の各項について、その語の読みを示し、対象語と「どのモーラが」どう違うか（一モーラ差・清濁・長音・促音の別）を述べる。

L3（文脈穴埋め）：
- 文インデックス {level_3_sentence_index} の文を使う。
- 正解 = その文に現れた対象語の形（その文の文字列と完全一致）。
- ディストラクター 3 つ：品詞が同じで、文法的にはその空所に入りうるが、意味／文脈上は不適切な語。
- 対象語の同音・近音語は使わない（音の混同は L1 に任せる）。
- 各ディストラクターはルール 5 の義項／役割一致を満たすこと。
- 必須の項目別自己点検（各ディストラクターを出す前に）：
  (a) 失効次元 — 各ディストラクターに、その文で失効する理由を次の 5 類から一つだけ付す：
        - "意味"   : 指す概念・カテゴリーが誤り
        - "連語"   : 周囲の語との結びつきが不自然
        - "アスペクト" : テンス・アスペクト（た／ている／てある等）が不整合
        - "語域"   : 丁寧度・領域・社会的場面がその文に不適合
        - "項構造" : 自他・格助詞・補語の取り方が誤り
      このラベルを選択肢 "3"（解説）の先頭に付す。例："意味：……"。
  (b) 置換監査 — 対象語をその一般的な類義語に心の中で置き換え、その上で問う：その類義語に替えたとき、このディストラクターは正解になりうるか？ なるなら直ちに却下して別のものに替える。
- 3 つのディストラクターは少なくとも 2 つの異なる失効次元をカバーすること。
- 最終点検：各ディストラクターを空所に入れて音読する。自然に通る項があれば直ちに差し替える。

L5（連語穴埋め）— 含まれる場合のみ生成：
- 文インデックス {level_5_sentence_index} の文を使う。
- 正解 = 主要連語相手（その文に連語として現れる）。
- ディストラクター 3 つ：正解の連語相手と品詞が同じで意味も近いが、対象語と結びつくと不自然になるか義項が変わる語。
- 解説：連語相手と対象語の固定的関係を指摘する。

L6（意味弁別）：
- 文インデックス {level_6_sentence_index} の文を正しい文として使う。
- 新たに 3 文を生成する。各文は対象語を使い、文法的には正しいが、意味／語用／連語の上で不自然または誤りであるようにする。誤り型は次から選ぶ（各文できるだけ別の型を）：
  - 助数詞の誤り（名詞類の対象語向け。例：「一冊の犬」→ 正しくは「一匹の犬」）；
  - 助詞の混同（は／が、に／で、を／が 等の取り違え）；
  - 活用・アスペクトの誤り（た／ている／てある 等の選択・位置の誤り）；
  - 語順・係り受けの誤り（時の副詞句の位置、主題—解説構造の破壊）。
- 各誤り文は対象語 {word} を含み、ルール 5 の義項／役割一致を満たすこと（誤りは他の構造層にある）。
- フィールド："1": テキスト，"2": 解説（具体的な誤り型と理由を指摘）。

出力スキーマ：
最上位キーはレベル番号の文字列。
L3 / L5 の値は 4 つの選択肢オブジェクト配列、L1 の値は 4〜6 個の選択肢オブジェクト配列：[{"1": テキスト, "2": 真/偽, "3": 解説}, ...]
L6 の値は：{"1": 正しい文のインデックス, "2": [3 つの誤り文オブジェクト {"1": テキスト, "2": 解説}]}

JSON のみを返すこと。コードブロックは使わないこと。
