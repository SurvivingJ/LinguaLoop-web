# Evidence-First Grading (Dual Translation v2)

## Purpose
Replace gestalt LLM banding with a grading framework where **every score is computed from
the specific errors found**, every error gets an **instance-specific explanation**, and the
grader's precision is **measured, not assumed**. This is the v2 framework for
[[features/dual-translation]] Feature 1; the shipped v1 remains documented in
[[algorithms/translation-grading-cascade]].

## Why v1 falls short

Analysis of the shipped code (`services/dual_translation/{prompts,grader_cascade,tier0}.py`,
rubric v2, taxonomy v4) found five structural gaps between v1 and the stated goal of
"specific and precise" feedback:

1. **Scores are ungrounded.** The model emits 1–4 band integers directly; nothing ties the
   band to the errors it reported. Two runs can find identical errors and band differently,
   and the learner can never be told *why* accuracy was a 3.
2. **Explanations are generic.** One template per (subtype, L1) means every `particle` error
   gets the same は/が lecture — even when the actual error was を vs に. The explanation
   layer cannot be specific because it never sees the specific error.
3. **The taxonomy is coarse.** 9 subtypes per language pair, versus ~80 error codes in the
   Cambridge Learner Corpus and 46 in the HSK learner corpus. Since remediation (Feature 2)
   is keyed by subtype, coarse subtypes mean mushy drills.
4. **Band descriptors are frequency-adverb boilerplate** ("frequent errors" / "a few minor
   errors"), which rubric research specifically warns against — raters (human or LLM) cannot
   count "frequent". And no few-shot exemplars are in the prompt, despite exemplar anchoring
   being the single biggest reliability lever in the LLM-scoring literature.
5. **Precision traps in the cascade.** Tier 0 awards full marks at ≤5% character mismatch —
   a は/が swap in a 50-character passage is ~2% and gets silently forgiven. Fail-open awards
   full marks on outage. A model that omits `confidence` defaults to 1.0 and never escalates.

## How It Works (v2, plain English)

**1. The model finds errors; the code computes scores.** The LLM's job narrows to what it is
good at — find, locate, classify, and correct every error, and credit difficult things done
well. Each error carries a severity (minor / major / critical, defined by reader-impact tests,
not vibes). Python then computes each rubric dimension's band from the severity-weighted sum
of the errors mapped to it, using published thresholds. Same errors ⇒ same score, every time.
The learner sees *"Accuracy 3 — one major particle error"*, not a bare number. A rubric change
re-scores past submissions **without any model calls**, because the stored errors are the
ground truth.

**2. Two model roles: Detector, then Verifier.** The first (cheap) call detects exhaustively,
guided by the Tier-0 character diff as candidate regions — every diff region must end up
explained as an error, a highlight, or acceptable variation. The second (mid) call re-judges
each proposed error (confirm / reject / adjust), hunts for what the diff can't expose (meaning
omissions, register mismatch), and judges the two genuinely holistic dimensions (naturalness,
range) — but only with cited text spans as evidence. Rejecting false alarms is an explicit,
first-class duty: precision is a graded behaviour, not a hope.

**3. Three-layer explanations.** Every error shows: the **Correction** (you wrote X → should
be Y), the **Rule** (the expert-authored per-subtype template, as today), and — new — the
**Application**: one or two model-written sentences in the learner's L1 explaining why the
rule bites *in this sentence, with these words*. The Application layer is generated by one
cheap batched call per submission, validated, and silently dropped to Rule-only if it fails
validation. This is what makes feedback *specific*.

**4. Positive evidence.** The detector reports up to three **highlights** — hard things the
learner got right (correct keigo, a tricky classifier). Feedback that only enumerates faults
demotivates and under-informs; confirmation of correct hypotheses is part of the learning
signal.

**5. Measured, not assumed.** Before any prompt changes ship, a per-L2 gold set (clean
passages + seeded single-error passages + adjudicated multi-error passages) baselines the
current grader. Every framework change is gated on span-detection F1, subtype accuracy,
false-positive rate on clean passages, and band agreement (QWK). "Is the grading precise?"
becomes a dashboard number, not an opinion.

## Research Foundations

- **Error-based analytic scoring** is the industry standard for translation quality: MQM
  (Multidimensional Quality Metrics) scores translations by classifying errors and summing
  severity weights (minor=1, major=5, critical=25) — never by holistic impression
  ([themqm.org scoring models](https://themqm.org/error-types-2/the-mqm-scoring-models/)).
  v2 adopts MQM's severity weights and derives bands from penalty sums.
- **Written corrective feedback works, and explicit beats implicit**: meta-analyses (Kang &
  Han 2015, [Modern Language Journal](https://onlinelibrary.wiley.com/doi/abs/10.1111/modl.12189);
  Brown, Liu & Norouzian 2023, [Bayesian meta-analysis](https://journals.sagepub.com/doi/abs/10.1177/13621688221147374))
  confirm WCF improves accuracy; Bitchener & Knoch (2010) show **direct correction plus
  metalinguistic explanation** has the most durable gains. v2's three-layer explanation is
  exactly direct correction + metalinguistic rule + instance application.
- **Focused remediation, comprehensive detection**: focused CF (small set of targets) yields
  greater long-term gains than scattershot; v2 therefore detects everything (the error profile
  and SRS need the data) but remediates selectively (Feature 2's promotion rule, unchanged).
- **Errors vs mistakes** (Corder 1967) already anchors the taxonomy; v2 operationalizes the
  test ("used correctly elsewhere in the same text ⇒ slip").
- **Feedback design**: Hattie & Timperley's feed-up / feed-back / feed-forward model and
  Nicol & Macfarlane-Dick's principles (feedback must clarify what good performance is,
  deliver high-quality information, and encourage positive motivational beliefs) shape the
  presentation: rubric shown before the attempt, computed "because" lines per dimension,
  highlights, and a "next focus" pointer into remediation.
- **Rubric craft**: descriptor quality research (Brookhart 2013) rejects frequency-adverb
  descriptors; v2 descriptors are behaviorally anchored and tied to the same thresholds the
  scorer computes with, so the words and the math agree. The CEFR Companion Volume's
  mediation scales ([Council of Europe 2020](https://rm.coe.int/cefr-companion-volume-with-new-descriptors-2020/16809ea0d4))
  inform the fidelity/understandability wording.
- **LLM-as-judge reliability**: exemplar anchoring nearly doubled human-agreement in essay
  scoring (QWK 0.306 → 0.531 with six anchors — [Song et al.](https://www.sciencedirect.com/science/article/pii/S1075293526000413));
  evidence-grounded judging (cite spans before scoring) measurably reduces drift
  ([arXiv 2601.08654](https://arxiv.org/abs/2601.08654)); practitioner guidance favours
  binary/checklist decisions over unanchored Likert scales
  ([Hamel Husain](https://hamel.dev/blog/posts/llm-judge/),
  [Eugene Yan](https://eugeneyan.com/writing/llm-evaluators/)). v2 applies all three:
  exemplars in the cached prefix, span-cited judgments, and confirm/reject verdicts.
- **Learner-corpus taxonomies** (Cambridge Learner Corpus ~80 codes —
  [Nicholls 2003](https://ucrel.lancs.ac.uk/publications/CL2003/papers/nicholls.pdf); NICT JLE
  tagset; HSK corpus 46 types) justify the taxonomy v5 expansion to ~15–17 subtypes per pair,
  including splitting JA `particle` into は/が vs case-particle vs other — different rules,
  different drills.

## Constraints & Edge Cases
- **L2-only prompts and numerical-index output are preserved** for both grading calls; only
  the learner-facing Application layer (a non-grading call) produces prose, in L1 (ADR-019).
- Level-neutral grading ([[decisions/ADR-018-level-neutral-grading]]) is unchanged: severity
  tests and thresholds are identical at every age tier; naturalness stays hidden at tiers 1–2.
- Anti-gamification rule unchanged: the headline remains the shrinking error profile, not the
  band ([[business-rules/translation-error-taxonomy]]).
- Cost: still two grading calls per unresolved submission; the verifier's input grows by the
  proposed-error list (~50–150 tokens); the explainer adds one cheap call only when errors
  exist. The re-score-without-model-calls property is a net cost win over time.
- Short passages: thresholds are absolute (per-passage) because passage length is controlled
  at selection (2–4 sentences); density normalization is deferred as an open refinement.

## Business Rules
- A dimension band must always be reconstructible from stored `dt_error_instance` rows plus
  the active rubric version. If it isn't, that's a defect.
- A rejected (verifier verdict) error is never shown to the learner and never persisted as an
  error instance; it is logged for eval only.
- The Application layer may never contradict the Correction; validation enforces that it
  mentions the actual forms, and falls back to Rule-only.
- Every prompt/rubric/taxonomy change requires an eval run against the gold set before
  activation (Phase 0 gate).
