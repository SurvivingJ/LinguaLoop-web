## TASK-989: Decide "all done" vs re-serving graded passages

**Status:** Done (2026-11-17)
**Feature:** fixes-2026-11-16 (dual-translation)
**Type:** feature
**Complexity:** XS (<1h)
**Depends On:** none

**Description:**
When every eligible passage in a language has been graded, `GET /api/dual-translation/next` returns
404 `ALL_DONE` and both clients show `dual_translation.error_all_done`. The alternative is to
re-serve the least recently graded passage. The engineer and reviewer recommend "all done": the
spec allows only content from completed tests; re-translating after seeing the gold diff tests
recall of the correction and distorts the error profile; practising past errors is the error cards'
job (still interleaved).

**Acceptance Criteria:**
- [ ] Owner records the choice in [[features/dual-translation]] (frontmatter open question resolved).
- [ ] If "re-serve" is chosen: step 4 in `_choose_next` serves the least recently graded passage and `TestNoRepeats::test_all_done_once_everything_is_graded` is replaced by a test for that order.

**Technical Notes:** `routes/dual_translation.py` `_choose_next` (final `return {'kind': 'none', ...}`).

**Files to Create / Modify:**
- `routes/dual_translation.py` — only if the decision changes behaviour
- `tests/test_dual_translation_next_selection.py` — matching test

**Verification:** `pytest tests/test_dual_translation_next_selection.py -q`.


**Resolution (2026-11-17):** owner chose "all done" first plus an explicit re-serve. `GET /next`
answers 404 `ALL_DONE`; both clients show the all-done screen with "Translate an earlier passage
again" (`?reserve=1`, least recently graded first) and "Browse tests". A repeat is graded but kept out
of the error profile, error cards, guided repair and word-knowledge evidence. **Verified on the real
app 2026-11-17** (zh test 41aa1ec3, 393x659): all-done screen, dock buttons 50/44 px, re-serve in
1.1 s showing "You translated this passage on 11/17/2026 (band 4). This try doesn't count towards
your error profile."; reviewer: repeat sub 112 → 0 `dt_error_instance`, 0 repair items.
