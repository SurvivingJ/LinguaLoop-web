# Session load latency — 2026-11-26

Owner report: "Sessions are slow to load." Measured from Supabase edge logs (one learner, ja,
2026-11-26 06:21–06:24 UTC) and the code; follow-up to [[evaluations/latency-2026-11-11]].

## The setting that multiplies everything

The app runs on Railway in **California**; Supabase is in **Sydney** (ap-southeast-2). Every
PostgREST / RPC / Storage round trip measured 170–550 ms origin time (typically ~200 ms warm,
~500 ms cold). A request that makes 20 sequential reads spends 4–10 s on the network alone. Moving
the Railway service to its Southeast Asia region (Singapore), or the database nearer the app, is
the largest single lever and needs no code; it is the owner's call (not done).

## What one session start did (before the changes)

- **`GET /api/study-session`** ~6–7 s: plan → today's load → tests → `new_word_state_inputs`
  → three parallel reads → five parallel nomination reads (one leg was `tests` then `questions`
  in sequence, ~1.3 s) → two `dim_word_senses` frequency reads → supply gate → ladder insert →
  `set_new_words_shortfall` → **re-read of `daily_test_loads`** (the shortfall write invalidated
  the cached row) → `new_word_state_inputs` again → parallel block reads, where the dt-repair leg
  re-read **`user_study_plans`** (its pool thread could not see the request cache) and
  `prestudy_plan_inputs` took up to 2.0 s. The supply-flag read also re-read `daily_test_loads`
  for the same reason.
- A second, overlapping `/api/study-session` (reload or second tab on the other gunicorn worker)
  doubled the work; both requests admitted new words (no per-learner lock: TASK-1240).
- **Practice block** ~10 s cold / ~4.4 s warm: plan read **alone before** the batch → RPC
  `get_practice_session` (1.2 s) beside two reads → untaught routing → intro rows → language check
  → `users.native_language_id` → `_load_senses` (×2) → exercises → 17 Storage files in parallel
  (~1.3 s each cold, 20 ms warm; 16-worker pool, so one waited) → **`_distractor_pool`, uncached,
  2.7 s cold / 0.3–0.5 s warm on every practice load**.
- Token checks: user tokens are **ES256**, so `SUPABASE_JWT_SECRET` local verification (HS256
  only) never applies; every new token on each worker costs a GoTrue call (~540 ms avg), cached
  60 s (`AUTH_CACHE_TTL_SECONDS`).
- Dimension tables (`dim_languages`, `dim_test_types`, `dim_exercise_capabilities`) were read
  ~70 times in 24 h: once per worker start, i.e. ~35 process starts a day (Railway restarts or
  sleeping; worth checking).

## Changes made (code, not deployed)

| Where | Change | Saves (per request, measured round trips) |
|---|---|---|
| `intro_drill.build_block` | senses, exercises+content, option pool run concurrently; option pool from the process-wide gloss pool (`definition_serving`) | 0.3–2.7 s + two sequential reads |
| `session_assembly.get_session` | plan row (+ follow-ups) and the learner's language read **beside** the session RPC; plan row and language seeded into the request cache for later steps | ~0.5–1 s |
| `_hydrate_items` | definition lookup and explanation-cache read run beside content hydration | the new features add no sequential read |
| `gloss_lookup.get_user_definition_language_id` | memoised per GET | duplicate `users` reads |
| `new_word_admission` | supply flags from the cached daily-load row; after `set_new_words_shortfall` the cached row is patched (the RPC sets exactly three target keys) instead of dropped | 1–2 `daily_test_loads` reads (0.2–0.6 s) |
| `_recent_test_sense_ids` | `tests` + `questions` in one embedded select | ~0.5 s on the slowest nomination leg |
| `repair.service.count_due` | uses the session's `today` instead of re-reading the plan on a pool thread | one read |

## Not changed (owner decisions)

1. Region (above).
2. ES256 local verification via the project JWKS, or a longer `AUTH_CACHE_TTL_SECONDS`: both trade
   revocation latency for ~0.5 s per token refresh per worker (TASK-1239).
3. `prestudy_plan_inputs` (up to 2 s cold) needs a SQL look.
4. `EXERCISE_CONTENT_FETCH_CONCURRENCY` 16 → 24 would remove the 17th-file straggler (env only).
5. Admission lock (TASK-1240) — correctness, not speed.
