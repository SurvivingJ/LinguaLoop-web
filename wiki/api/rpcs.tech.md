# API — Technical Specification

This is the route-to-function reference. Every route the Flask `url_map` registers is listed with its handler, its auth requirement and the RPCs and tables it reaches.

**How this page was verified (2026-11-23).** The route tables were generated by importing the application with dummy credentials (`LINGUADOJO_SKIP_DOTENV=1`, `DISABLE_SCHEDULER=true`) and printing `app.url_map`; the handler, auth and RPC columns were then read from the code. Code basis: the merged session branch at commit `0d345e98` (the 2026-11-23 review fixes, the vocabulary placement and the knowledge report on top of `main`); the route list was regenerated from the merged tree and is identical. **Registered: 116 `url_map` rules (89 under `/api/`, 24 page routes, 2 login redirects and Flask's own `/static/<path:filename>`); documented below: the 89 API routes and the 26 page and redirect routes. Before the 2026-11-23 unused-route removal (TASK-1221) the same count was 136, of which 109 under `/api/` (the 137 and 111 stated earlier predate the removal of the token routes).** RPC existence was checked read-only against the live database (`pg_proc`, project `kpfqrjtfxmujzolwsvdq`) the same day. "Client" says whether `static/` or `templates/` contains a caller; after TASK-1221 no route in the table lacks a caller; a route that a test alone calls counts as unused. The owner confirmed on 2026-11-23 that no other tool or app calls the API, so absence of an in-repo caller is a sufficient reason to remove a route.

Related: [[api/rpcs]] (prose), [[overview/project.tech]] (architecture, scheduler, gates), [[features/web-package.tech]] (how `create_app` wires everything), [[features/routes-tests-package.tech]] (the `/api/tests` package), [[database/rpcs.tech]] (RPC definitions).

## Application wiring in one paragraph

`wsgi.py` calls `create_app()` in `app.py`. The factory validates `Config`, builds the Flask app behind `ProxyFix`, turns strict slashes off, sets CORS (`/api/*` only), then installs the `web/` pieces in this order: security headers and the request-size limit, static-asset versioning and compression, the external services, the scheduler (skipped when `TESTING`), the blueprints, the error handlers, the four inline core routes, the page routes, and last the rate limits (which attach to endpoints by name, so every route must exist first). Details and the order guarantees are in [[features/web-package.tech]]. Production runs `gunicorn wsgi:app --workers 2 --worker-class gthread --threads 8 --timeout 120` (`Procfile`): **two worker processes**, so every in-process structure (rate-limit counters, the scheduler, the DT submit lock, the exercise-content cache) exists twice.

## Authentication

All decorators are in [middleware/auth.py](../../middleware/auth.py). The token is `Authorization: Bearer <jwt>`; the server sets `g.current_user_id` (also `g.supabase_claims`, `g.current_user`); the client can never set them.

| Decorator | Behaviour | Failure |
|---|---|---|
| `@jwt_required` (alias `@supabase_jwt_required`) | Resolves the token in this order: (1) `BATCH_SERVICE_TOKEN` env var, compared in constant time, yields the synthetic identity `sub='service-account'`, `role='service_role'` (ADR-014; **the Supabase service-role key is no longer accepted**); (2) a revoked-token check and a short validation cache; (3) local HS256 verification when `SUPABASE_JWT_SECRET` is set; (4) otherwise `auth.get_user(token)` against Supabase. | `401 {"error":"Token missing"}` / `401 {"error":"Invalid or expired token"}` / `503 {"error":"Authentication service unavailable"}`. These three bodies have **no** `status` field (they are built in the middleware, not by `utils/responses`). |
| `@admin_required` | JWT (as above, but the batch identity is **not** honoured) and `users.subscription_tier_id → dim_subscription_tiers.tier_code ∈ {admin, moderator}`. | `403 {"error":"Admin access required"}` |
| `@tier_required([...])` | Same, for a given tier list. Defined; no route in `routes/` uses it. | `403` |
| `get_optional_user_id(request)` | Best-effort identity for routes that stay public but personalise when a valid token is present. Never raises. Used by `GET /api/tests/<slug>`, `GET /api/tests/test/<identifier>` and by the rate limiter's key function. | — |
| no decorator | Public. | — |

## Responses and errors

`utils/responses.py`: `api_success(data)` → `{"status":"success", ...data}` (fields spread at the top level, not under `data`); `api_error(message, status, error_code, details)` → `{"status":"error","error":..., "error_code"?:..., "details"?:...}`; helpers `bad_request` 400, `not_found` 404, `forbidden` 403, `unauthorized` 401, `server_error` 500, `service_unavailable` 503; `@api_errors("message")` names the client message for an unhandled exception in that route.

`web/errors.py` turns every uncaught exception and every HTTP error under `/api/` into the same envelope: `400 BAD_REQUEST`, `401 UNAUTHORIZED`, `403 FORBIDDEN`, `404 NOT_FOUND ("Endpoint not found")`, `405 METHOD_NOT_ALLOWED` (also for non-API paths), `413 PAYLOAD_TOO_LARGE`, `429 RATE_LIMITED`, `500 SERVER_ERROR`, `503 SERVICE_UNAVAILABLE`, `402 PAYMENT_REQUIRED`. Outside `/api/` an unknown URL (404) **redirects to `/login`**, a 5xx renders `templates/error.html`. The auth routes in `routes/auth.py` and the three middleware failures above predate the envelope and return `{"error": ...}` or `{"success": false, ...}` bodies.

Rate limits (`web/rate_limits.py`): every `/api/` route is limited to `300 per minute` per verified user id, else per client IP (`/api/health` and the batch identity are exempt); the stricter per-endpoint limits are listed in the notes below. Counters are in process memory unless `RATELIMIT_STORAGE_URI` points at Redis, so with two workers a client can reach about twice each limit.

## `/api/auth` — [routes/auth.py](../../routes/auth.py)

OTP passwordless login. `auth_bp.auth_service` (`AuthService`) and `auth_bp.device_service` (`DeviceService`) are bound by `app._register_blueprints`. Bodies are `{"success": bool, ...}` or `{"error": ...}`, not the `api_success` envelope. The refresh token never travels in a JSON body: it is an HttpOnly, `SameSite=Lax` cookie scoped to `/api/auth`; the trusted-device cookie is HttpOnly too. Cookie-bearing POSTs check `Origin` (same host or in `CORS_ORIGINS`, else `403`).

| Method | Path | Handler | Auth | Notes | Client |
|---|---|---|---|---|---|
| POST | `/api/auth/send-otp` | `auth.send_otp` | none; limit 5/min, 20/h per IP and 3/10 min, 10/day per email | `{email, is_registration?}` → Supabase Auth OTP. `400` bad email or failed send. | `login.js` |
| POST | `/api/auth/verify-otp` | `auth.verify_otp` | none; 10/min, 60/h per IP and 10/10 min per email | `{email, otp_code, remember_device?}` → `{success, user{id,email,emailVerified,subscriptionTier,totalTestsTaken,totalTestsGenerated,hasSeenWelcome}, jwt_token, remembered}`; sets the refresh cookie (persistent only when `remember_device`) and, if remembered, the device cookie. Creates the `users` row on first login (`AuthService._get_user_data`; no token grant is attempted since 2026-11-23, and `tokenBalance` was removed from the payload, TASK-1210). | `login.js` |
| POST | `/api/auth/refresh-token` | `auth.refresh_token` | none (cookie); 60/min per IP | Reads the refresh cookie, rotates it, returns `{success, jwt_token}`. `400` no cookie, `401` rejected. | `base.js` |

| GET | `/api/auth/profile` | `auth.get_profile` | JWT | `AuthService.get_user_profile` (reads `users`). `404` when no row. | `login.js` |
| POST | `/api/auth/mark-welcome-seen` | `auth.mark_welcome_seen` | JWT | Idempotent flag on `users`. | `onboarding.js` |

### `POST /api/practice/attempt` — the recording path

Body: `exercise_id` (required; ids starting `virtual-` return `{virtual:true}` without a write), `is_correct` (required), `user_response?`, `time_taken_ms?` (clamped), `expected_seconds?`, `session_mode?` (`acquisition`\|`maintenance`), `language_id?`, `tail`/`is_tail?`, `exercise_context?` (`standard`\|`gate`\|`stress_test`), `is_speed_round?`, `timed_out?`. Gate or stress markers are refused (`400`: they go through `/api/vocab-dojo/*`).

1. **Server-side grading of typed answers.** For `cloze_typed` items (`_SERVER_GRADED_TYPES`) the route re-grades `user_response.typed` against the hydrated exercise content (`vocabulary_ladder.deterministic.cloze_typed.grade`) and overwrites `is_correct`; it fails open (the client's verdict stands) when the item cannot be loaded.
2. **Speed-round attempts** (`is_speed_round`) go to `record_speed_round_attempt`: FSRS only, never the ladder.
3. **Everything else** goes to `record_attempt_with_updates`, which makes **one RPC call, `record_exercise_attempt`** (`migrations/record_exercise_attempt.sql`; there is no flag and no Python fallback: `PRACTICE_ATTEMPT_RPC_ENABLED` was removed and is ignored if set). Inside one transaction, under a per-user-and-exercise advisory lock, it: decides first-attempt-ness, inserts `exercise_attempts`, increments the `exercises` counters (steps 1–3 failing fails the whole call, nothing is recorded, the route answers 500), and then best-effort in sub-blocks (a failure is reported in `warnings` and does not undo the attempt): completes prestudy follow-ups, applies BKT with frequency inference and the p_known capture (first attempts only), calls `ladder_apply_progress`, calls `credit_study_time` (`p_credit_seconds` = measured time, or `expected_seconds` when the measure is missing, zero or over 5 minutes), and calls `record_session_progress` when `p_plan_kind` is given (only when `STUDY_PLAN_ENABLED` and `session_mode` is set).
4. **In Python afterwards:** the RPC returns the learner's `user_flashcards` row; `_apply_fsrs_review` rates it (wrong → Again; correct in under 5 s → Easy; else Good), writes the new schedule with `services/vocabulary/fsrs.schedule_review`, and on a lapse calls RPC `bkt_apply_lapse_penalty`; `_report_ladder_progress` shapes `result.ladder` and may restart the new-word drill after a demotion (`intro_drill.restart_if_demoted`).
5. **Response** `{attempt_id, is_correct, exercise_type, is_first_attempt, bkt_update?, ladder?}`; `{error:'Exercise not found'}` from the RPC becomes a 500.

### `POST /api/dual-translation/<submission_id>/submit`

Body `{reproduction, idempotency_key?, primed_token?, active_ms?}`. Order of events:

1. **Validate:** a missing or non-object body or an empty `reproduction` is `400`; invisible and control characters are stripped first (`output_sanitizer.clean_learner_text`); longer than `MAX_REPRODUCTION_CHARS` (2000) is `400 REPRODUCTION_TOO_LONG`. Unknown submission `404`; someone else's `403`.
2. **Per-submission in-process lock.** `_SubmissionLock(submission_id)` takes a `threading.Lock` kept in a module dict (`_submit_locks`) and waits at most `_SUBMIT_LOCK_WAIT_S = 90` seconds. A second submit of the same submission handled by the **same worker** waits for the first, then normally finds the stored grade through `_cached_grade` and returns it instead of grading again. After 90 seconds it logs a warning and proceeds anyway. The lock is released in a `finally`, and the dict entry is removed when the last holder or waiter leaves.
3. **Cached grade.** A submission already graded returns the stored grade (`200`, idempotent; `dt_grade.submission_id` is UNIQUE), with the guided-repair session attached (`repair_hooks.for_cached`) unless it was a repeat.
4. **Pre-grading reads run concurrently** (`run_parallel`: the passage, the repeat-of lookup, today's token use); results are unpacked in the old serial order so a failure surfaces as before. A passage that is not `active` is `400 PASSAGE_RETIRED`; at or over `DT_DAILY_TOKEN_BUDGET` (20000 by default) grading is capped at tier 1. A bad `primed_token` is `400`.
5. **Grade:** `grader_cascade.grade_submission`. If the provider refused every call and nothing answered: `503 GRADING_UNAVAILABLE`, nothing stored. A contract with no `overall_band`, or one that fails `contract_problems`, is returned `200` as provisional and **not stored**, so a retry grades again.
6. **Persist** (`_persist_grade`): the reproduction on `dt_submission`, the `dt_error_instance` rows, and the `dt_grade` row **last**. If the `dt_grade` insert fails, `_discard_error_rows` removes this request's own error rows before the exception propagates. The handler then reads `_cached_grade`: if another submit stored a grade in the meantime (typically another gunicorn worker), the learner gets **that stored grade as a `200`** and this request's grade is dropped; with no stored grade the failure is a real `500`.
7. **After the grade:** repeats (the learner already had this passage graded) store their errors on `dt_grade.grader_trace.repeat` only and create no error rows, repair session or target-word evidence; otherwise `repair_hooks.after_grade` builds the response, target-word BKT evidence is recorded, the prestudy Produce result is stored, and `credit_study_time` (kind `dual_translation`, `active_ms` clamped) runs once.

**Limits with several workers (`Procfile`: 2 workers).** The lock is per process. Two concurrent submits that land on different workers each grade (two grader calls, double cost) and race on the unique `dt_grade` insert; the loser cleans up its own error rows and returns the winner's grade, so the stored data stays consistent, but the grading work is not de-duplicated. Nothing serialises across processes.

## Removed routes (history)

For readers of older pages: the exercises route module (`/api/exercises/*`) and the exercise-session service were deleted, their behaviour now lives in `services/practice/` and `services/study_session/` (the daily session is `GET /api/study-session` plus `/api/practice/*`); the mystery and conversations route modules and the pack endpoints of `routes/corpus.py` were archived 2026-09-21 (`archive/modules/*.zip`, tables dropped 2026-09-22); the Model Arena and local-admin route modules, the local admin app and its task-runner service no longer exist, so no `/admin/*` API remains (the only `/admin/` URL is the public page `/admin/vocab-preview`); `GET /api/vocab-dojo/session`, `/attempt` and `/word/<id>/exercises` were removed with the per-word dojo UI; `/api/payments/*` and `GET /api/users/tokens` were removed with the token economy (2026-11-23).

**Removed 2026-11-23 as unused (TASK-1221; owner: no other tool or app calls the API).** 20 routes, each re-checked against `static/`, `templates/`, `routes/`, `services/`, `scripts/`, `scratch_offline/`, the skills, the e2e specs, CI, `Procfile` and `Portal/` and found to have no caller: `GET /api/config`; `POST /api/vocabulary/extract`; `POST /api/errors/log`; `POST /api/tests/moderate`; `GET /api/users/profile`; `GET /api/calibration/ability`; `GET /api/flashcards/page`, `/stats` and `POST /skip`; `GET /api/dual-translation/cards/due`; `POST /api/dual-translation/passage-from-sentences` (its core `open_range_passage` stays: the prestudy Produce route calls it); the whole `/api/corpus` blueprint (`POST /ingest`, `POST /style-analyze`, `GET /style-profile/<id>`; `services/corpus/` stays, scripts use it); and six of the seven `/api/admin/vocab` routes (`upload-words`, `generate-assets`, `render-exercises`, `words`, `word/<id>/wipe`, `word/<id>/level/<n>`; only `preview` remains). A request to any of them now gets the generic `404 NOT_FOUND` envelope (`405` for `POST /api/tests/moderate`, which lies under the `GET /api/tests/<slug>` rule). `tests/test_removed_unused_routes.py` pins this. Kept although the earlier review listed it: `GET /api/tests/` (called by `static/js/pages/test-list.js` as `/api/tests?...`).
