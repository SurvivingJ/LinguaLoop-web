How to read this. Rates are per minute, so a quick type that moves knowledge a little can legitimately beat a slow type that moves it a lot — learner time is the scarce resource. Compare types within a bucket; across buckets the numbers are not comparable, because a word at 0.8–1.0 has almost no headroom left to gain.

What is counted. Only attempts where BKT actually ran, so both p_known_before and p_known_after were captured, and where time_taken_ms is positive. Per-attempt time is capped at 5 minutes so an abandoned tab cannot make a type look worthless. Rows marked thin have fewer than {{ min_attempts }} attempts; read the rate as provisional.

A negative rate is a real signal, not a bug: BKT lowers p_known on a wrong first attempt, so a type that mostly catches learners out will sit below zero.
